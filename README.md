# Путь к себе — Владивосток

Полноценный сайт психологического центра для предпринимателей и их семей. Проект включает публичные страницы, программы, специалистов, отзывы, формы заявок и административную панель.

Фотографии направлений на главной и в списке программ показываются целиком, в исходных пропорциях, без обрезки и увеличения при наведении. Для «Стратегической сессии» установлено новое предоставленное фото. В описании команды на странице специалистов «семьями» заменено на «лидерами». Формы, CRM, аналитика и настройки индексации не менялись.

### Расширенная CMS Beget

Рабочая панель: `https://putksebevladivostok.ru/admin/`. Управляет основным сайтом на Beget; GitHub Pages остаётся отдельной статической демонстрацией без синхронизации пользовательских правок.

- Страницы сгруппированы на основные, специалистов и мероприятия/архив; разделы и карточки раскрываются отдельно, доступны поиск полей и предупреждение о несохранённых изменениях.
- Редактируются тексты, заголовки, изображения/alt/режим показа, ссылки, видео и обложки. Карточки и пункты списков можно копировать, переставлять и скрывать; раздел страницы можно временно скрыть.
- Есть черновик, закрытый предпросмотр, отдельная публикация страницы/общих элементов, история предыдущих публикаций и восстановление в черновик. Устаревшая вкладка не перезаписывает свежую правку.
- Новые страницы создаются по существующему шаблону. Профили используют адрес `specialisty/<slug>`; новые опубликованные профили регистрируются в обработчике формы. Ссылки-карточки на новые страницы добавляются отдельно; снятие дополнительной страницы с публикации сохраняет черновик.
- Единые контакты, город и адрес связаны между предусмотренными размещениями; шапка, пункты меню, подвал и мессенджеры имеют отдельный редактор.
- Медиатека принимает проверенные JPG/PNG/WebP/PDF до 20 МБ и MP4 до 100 МБ, с учётом меньших лимитов PHP. Файлы получают SHA-256-имена и фиксированные расширения; SVG/HTML/скрипты не принимаются. Файлы публичны, их нельзя использовать для личных документов клиентов. Загрузка сама по себе не меняет страницу.
- Документы, реквизиты, SEO, заявки и интеграция сохранены. SEO/реквизиты/ссылка теста применяются своими кнопками сразу, а не через публикацию контента. Редактор не изменяет существующие записи CRM и не создаёт тестовых заявок.
- Владелец может самостоятельно сменить пароль в настройках (минимум 14 символов); сессии привязаны к хешу пароля и после смены требуют повторного входа. Пароли и токены не включаются в сборку или руководство.

`scripts/build-cms-schema.php` размечает контролируемые HTML-шаблоны и создаёт закрытую `.cms-schema.json`. Для Beget-сборки нужны PHP CLI с DOM и mbstring. `beget/editor.php` применяет только разрешённые поля, экранирует текст, проверяет URL/типы медиа и сохраняет атомарные JSON-версии вне `public_html`. Несовместимые с новым исходным шаблоном значения не применяются молча и требуют повторного сохранения поля; значения остаются в частном хранилище и истории. При изменениях событий/услуг не наследуются устаревшие структурированные даты/цены из шаблона.

Данные CMS: `editor-<sha256(scope)>.json`, `editor-pages.json`, `editor-media.json`, `editor-history-*.json` в существующей частной папке. Заявки и конфигурация интеграции не входят в историю контента и не откатываются ею. Публикация кода не должна очищать частную папку и `/images/uploads/`.

Руководство: `docs/admin-guide.pdf` (9 страниц), после сборки отдаётся по `/admin/instruction/` только авторизованному владельцу. Прямой доступ к скрытому PDF и внутренним PHP/JSON-файлам закрыт. Проверены 21 функциональный сценарий на изолированной копии, публичные страницы/ресурсы, а также реальное сохранение, публикация и возврат через рабочую панель без обращений к CRM.

## Стек

- Next.js / React / TypeScript
- Vinext и Cloudflare Workers
- Cloudflare D1 и Drizzle ORM
- адаптивная вёрстка без внешнего UI-конструктора

## Локальный запуск

Требуется Node.js `>=22.13.0`.

```bash
npm ci
npm run dev
```

Проверки перед публикацией:

```bash
npm run lint
npm run build
```

## Структура

- `app/` — страницы, API и глобальные стили;
- `components/` — шапка, подвал, формы и интерфейсные компоненты;
- `lib/` — данные по умолчанию и серверный слой контента;
- `db/` и `drizzle/` — схема и миграции D1;
- `public/` — изображения и статические ресурсы;
- `scripts/build-pages-demo.mjs` — сборка безопасной статической демоверсии для GitHub Pages.

## GitHub Pages

Проект требует SSR, Cloudflare D1 и серверных API, поэтому полноценный движок нельзя запустить на GitHub Pages. В ветке `gh-pages` публикуется статическая демонстрация интерфейса.

Собрать её локально:

```bash
npm run pages:build
```

Результат появляется в игнорируемой директории `.pages-demo/`. Все страницы демоверсии содержат `noindex`, а `robots.txt` запрещает обход сайта.

В статической версии отключены:

- отправка форм и сохранение заявок;
- административная панель и редактирование контента;
- D1 и серверные API;
- серверная авторизация;
- динамические изменения из базы данных.

Основной React/Vinext-движок рассчитан на платформу с поддержкой Cloudflare Workers и D1. Для текущего Beget подготовлен отдельный PHP-адаптер с предварительно сформированным HTML, документами, SEO-полями и формами записи.

## Запись, CRM, Telegram, оплата и расписание

На страницах всех специалистов размещены блоки записи с привязкой заявки к выбранному специалисту. В оригинальном движке API `/api/leads` сохраняет заявки в D1. На Beget приём заявок включён по решению владельца независимо от утверждения документов; обязательное отдельное согласие, CSRF, ограничения частоты и защита от повторной записи сохранены. В журнале заявки фиксируются хеши показанных текстов и их статус утверждения. Реквизиты нужно заполнить в CMS до полноценной работы с персональными данными. На GitHub Pages кнопка записи ведёт к реальной форме выбранного специалиста на основном домене. Прямой контакт доступен через WhatsApp, телефон и Telegram. Платежи, автоматическое расписание и Telegram-бот не подключены.

Для полноценного запуска нужны:

- Рабочий сервер приложения и база. Текущий движок предназначен для Cloudflare Workers/D1; обычная загрузка статических файлов на Beget не запускает его API. Для Beget понадобится отдельная серверная адаптация или подходящий VPS с поддержкой выбранного серверного стека. Основной домен должен работать по HTTPS.
- Выбранная CRM, её адрес, доступ для интеграции, воронка, ответственный и соответствие полей. Создание заявок поддерживают [REST API Битрикс24](https://apidocs.bitrix24.ru/api-reference/crm/leads/crm-lead-add.html) и [API amoCRM](https://www.amocrm.ru/developers/content/crm_platform/leads-api).
- Telegram-бот, созданный владельцем через BotFather, и чат сотрудников для уведомлений. Потребуются токен бота и ID чата. Секреты настраиваются только на сервере, не в исходниках и не в браузере. Отправка уведомлений — через [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage). В сообщении достаточно номера заявки, имени, телефона и специалиста; описание психологического запроса остаётся в системе с ограниченным доступом.
- Для предоплаты: подключённый платёжный провайдер, реквизиты магазина и серверные ключи, утверждённые цены, размер предоплаты и правила отмены/возврата. Например, [ЮKassa](https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start) поддерживает создание платежа и переход на платёжную страницу. Подтверждать оплату нужно по проверенному статусу на сервере; повторные уведомления не должны создавать повторные записи. Сначала тестовый режим, затем активация приёма настоящих платежей.
- Для свободных окон: единый календарь записи с графиком каждого специалиста, длительностью услуг, перерывами, выходными, часовыми поясами и отменами. CRM и календарь должны использовать один источник расписания. Если два клиента выбирают одно время, сервер бронирует его только одному. Скачивать приложение клиентам не требуется — запись может работать в браузере; сотрудникам нужен доступ к выбранной системе.
- Прямая публичная ссылка администратора в Telegram. Пока запись в Telegram открывается по номеру через приложение; канал центра имеет отдельную публичную ссылку.
- Фото и видео для архива мероприятий. Раздел готов к наполнению; материалы ещё не предоставлены.

Предлагаемый порядок запуска: сервер и база → сохранение заявок → CRM и уведомления → расписание → тестовая предоплата → приём реальных платежей. По ТЗ от 06.10 индивидуальный подбор включает бесплатное интервью, консультации всех специалистов — от 7 000 ₽; точная стоимость и длительность согласовываются индивидуально.

## Безопасность репозитория

`.gitignore` исключает `.env*`, локальные базы, `.wrangler`, `node_modules`, результаты сборки, логи, архивы и временные файлы. Секреты и реальные данные заявок не должны добавляться в Git.
