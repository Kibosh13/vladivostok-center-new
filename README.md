# Путь к себе — Владивосток

Полноценный сайт психологического центра для предпринимателей и их семей. Проект включает публичные страницы, программы, специалистов, отзывы, формы заявок и административную панель.

## Стек

- Next.js / React / TypeScript
- Vinext и Cloudflare Workers
- Cloudflare D1 и Drizzle ORM
- адаптивная вёрстка без внешнего UI-конструктора

## Локальный запуск

Требуется Node.js `>=22.13.0`.

```bash
npm ci
npm run dev
```

Проверки перед публикацией:

```bash
npm run lint
npm run build
```

## Структура

- `app/` — страницы, API и глобальные стили;
- `components/` — шапка, подвал, формы и интерфейсные компоненты;
- `lib/` — данные по умолчанию и серверный слой контента;
- `db/` и `drizzle/` — схема и миграции D1;
- `public/` — изображения и статические ресурсы;
- `scripts/build-pages-demo.mjs` — сборка безопасной статической демоверсии для GitHub Pages.

## GitHub Pages

Проект требует SSR, Cloudflare D1 и серверных API, поэтому полноценный движок нельзя запустить на GitHub Pages. В ветке `gh-pages` публикуется статическая демонстрация интерфейса.

Собрать её локально:

```bash
npm run pages:build
```

Результат появляется в игнорируемой директории `.pages-demo/`. Все страницы демоверсии содержат `noindex`, а `robots.txt` запрещает обход сайта.

В статической версии отключены:

- отправка форм и сохранение заявок;
- административная панель и редактирование контента;
- D1 и серверные API;
- серверная авторизация;
- динамические изменения из базы данных.

Основной React/Vinext-движок рассчитан на платформу с поддержкой Cloudflare Workers и D1. Для текущего Beget подготовлен отдельный PHP-адаптер с предварительно сформированным HTML, документами, SEO-полями и формами записи.

## Beget: обновление от 13–14 октября

```bash
npm run beget:build
```

Результат `.beget-build/` не хранится в Git. Нужен PHP 8.1+ (на основном домене выбран 8.3), расширения curl и mbstring. В `beget/` находятся контроллер, защищённая CMS и обработчик форм. Веб-сервер должен применять включённый `.htaccess`; локальная проверка использует `dev-router.php` только с `PS_DEV=1`.

- На основном домене разрешена индексация, настроены индивидуальные метатеги, canonical, фактическая JSON-LD-разметка, robots.txt, динамический sitemap.xml и llms.txt. Демонстрация GitHub Pages остаётся закрытой от индексации.
- Кнопки индивидуального подбора открывают шесть существующих специалистов. В профиле форма привязана к выбранному специалисту. Общий слайд «Первый шаг — Индивидуальный подбор» удалён.
- Контакты и соцсети объединены; старые адреса `/socialnye-seti/`, `/kontakty/` и `/o-centre/` перенаправляются на актуальные разделы. MAX удалён из интерфейса.
- Заменены фото главной и Татьяны Васильевой. Мастер-класс «Где деньги?» перенесён на 22 октября; прошедшая встреча 29 сентября находится в архиве.
- Google-файл подтверждения размещается в корне без изменения содержимого.

CMS `/admin/` на Beget редактирует семь юридических документов, SEO-поля и ссылку на Яндекс Форму; показывает только заявки данного сайта. Это не замена редактору всех программ/специалистов оригинального D1-движка. Существующая авторизация Sites в исходном движке сохранена.

Приватные настройки и заявки находятся в соседней с `public_html` папке `.put-k-sebe-private/`, с правами 0700 на каталог и 0600 на файлы. `config.json` содержит серверный секрет, хеш пароля администратора и токен отдельной интеграции amoCRM; никогда не копируйте его в сборку, исходники, архивы или Git. Для первичной активации владелец берёт одноразовый код из закрытого `activation-code.txt` в файловом менеджере Beget и самостоятельно вводит новый логин и пароль (не менее 14 символов). После активации код удаляется и больше не действует.

Семь готовых текстов находятся в `beget/legal-templates.json`. На Beget владелец заполняет только неизвестные реквизиты оператора, сроки, сведения об обработчиках и условия услуг: общие поля автоматически подставляются во все документы. Полного редактируемого поля «текст документа» в этой CMS больше нет. Проекты доступны для ознакомления и закрыты от индексации; они не выдаются за утверждённые согласия. Публикация блокируется при недостающих обязательных полях. После изменения реквизитов ранее утверждённый шаблон требует повторной проверки; заявки сохраняют хеши реально показанных текстов. Любой ранее введённый владельцем непустой текст сохраняется и не заменяется шаблоном автоматически.

Информация о cookies описывает фактически работающий сайт и доступна сразу. Баннер просит согласие понятным языком, с прямыми ссылками на документы и выбором «Согласен» / «Только необходимые». Выбор сохраняется локально не дольше шести месяцев; «Настройки cookies» открывают баннер повторно. Аналитические и рекламные счётчики не подключены. Cookie-выбор не заменяет отдельное согласие в форме и не включает рекламу. Пока политика и согласие для заявки не утверждены, форма не принимает персональные данные. Рекламное согласие остаётся отдельным и необязательным.

Настоящая ссылка на Яндекс Форму пока не предоставлена. После её добавления в CMS кнопки сразу открывают форму. На странице указано, что расшифровку лично делает Алёна Савинова; тест и баллы не выдуманы, WhatsApp не выдается за прохождение теста.

Адаптер amoCRM имеет жёсткую серверную allowlist: чтение `/api/v4/account` для проверки авторизации и создание новых входящих `/api/v4/leads/unsorted/forms`. Нет операций изменения/удаления/объединения/принятия существующих сущностей, настройки воронок и вебхуков. При неопределённом результате отправка автоматически не повторяется: собственная заявка сохраняется в закрытой очереди для ручной проверки. 14 октября 2026 владелец отдельно разрешил одну тестовую заявку. Её создание и чтение по полученному UID подтверждены API, а карточка №30679445 проверена в кабинете. Уже существующий SalesBot перевёл только эту новую заявку в этап «новая сделка»; настройки бота не менялись. Тестовая запись сохранена, не удалена.

## Запись, CRM, Telegram, оплата и расписание

На страницах всех специалистов размещены блоки записи с привязкой заявки к выбранному специалисту. В оригинальном движке API `/api/leads` сохраняет заявки в D1. На Beget используется описанный выше PHP-адаптер: приём заявок зависит от публикации документов и настройки интеграции. На GitHub Pages отправка форм отключена. Прямой контакт доступен через WhatsApp, телефон и Telegram. Платежи, автоматическое расписание и Telegram-бот не подключены.

Для полноценного запуска нужны:

- Рабочий сервер приложения и база. Текущий движок предназначен для Cloudflare Workers/D1; обычная загрузка статических файлов на Beget не запускает его API. Для Beget понадобится отдельная серверная адаптация или подходящий VPS с поддержкой выбранного серверного стека. Основной домен должен работать по HTTPS.
- Выбранная CRM, её адрес, доступ для интеграции, воронка, ответственный и соответствие полей. Создание заявок поддерживают [REST API Битрикс24](https://apidocs.bitrix24.ru/api-reference/crm/leads/crm-lead-add.html) и [API amoCRM](https://www.amocrm.ru/developers/content/crm_platform/leads-api).
- Telegram-бот, созданный владельцем через BotFather, и чат сотрудников для уведомлений. Потребуются токен бота и ID чата. Секреты настраиваются только на сервере, не в исходниках и не в браузере. Отправка уведомлений — через [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage). В сообщении достаточно номера заявки, имени, телефона и специалиста; описание психологического запроса остаётся в системе с ограниченным доступом.
- Для предоплаты: подключённый платёжный провайдер, реквизиты магазина и серверные ключи, утверждённые цены, размер предоплаты и правила отмены/возврата. Например, [ЮKassa](https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start) поддерживает создание платежа и переход на платёжную страницу. Подтверждать оплату нужно по проверенному статусу на сервере; повторные уведомления не должны создавать повторные записи. Сначала тестовый режим, затем активация приёма настоящих платежей.
- Для свободных окон: единый календарь записи с графиком каждого специалиста, длительностью услуг, перерывами, выходными, часовыми поясами и отменами. CRM и календарь должны использовать один источник расписания. Если два клиента выбирают одно время, сервер бронирует его только одному. Скачивать приложение клиентам не требуется — запись может работать в браузере; сотрудникам нужен доступ к выбранной системе.
- Прямая публичная ссылка администратора в Telegram. Пока запись в Telegram открывается по номеру через приложение; канал центра имеет отдельную публичную ссылку.
- Фото и видео для архива мероприятий. Раздел готов к наполнению; материалы ещё не предоставлены.

Предлагаемый порядок запуска: сервер и база → сохранение заявок → CRM и уведомления → расписание → тестовая предоплата → приём реальных платежей. По ТЗ от 06.10 индивидуальный подбор включает бесплатное интервью, консультации всех специалистов — от 7 000 ₽; точная стоимость и длительность согласовываются индивидуально.
